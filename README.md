# Network Inventory AI Assistant

A retrieval-augmented (RAG) **Claude tool-calling agent** that answers questions about an Outside Plant (OSP) network inventory and flags data-quality exceptions. It searches the engineering documentation for the rules, writes its own read-only SQL, and is scored against a rule-based SQL answer key.

> All data is **synthetic** (generated by `nia/generate_data.py`). The documentation in `docs/` is written for this project and is not taken from any operator.

## Why

OSP inventory lives in several systems: NRI (Network Resource Inventory), GIS and DFF (Digital Field Force). Analysts spend time on repetitive checks such as duplicates, orphan references, over-capacity assets, NRI vs GIS reconciliation and overdue work orders. This project tests whether an AI agent can answer those questions in plain language with the right business rules, and measures how far its answers can be trusted.

## How it works

```
question ──► Claude agent ──► search_docs  (TF-IDF retrieval over docs/*.md sections)
                         ├──► get_schema
                         └──► run_sql      (DuckDB, read-only, file access disabled)
                    answer + cited rule + {"record_ids": [...]}
                                   │
            evaluate.py compares ──┴──► SQL checks (nia/checks.py) = answer key
```

| Component | File | Notes |
|---|---|---|
| Synthetic inventory | `nia/generate_data.py` | 6 tables (manholes, ducts, cables, splitters, GIS routes, work orders); 98 injected anomalies across 12 types, logged to `data/injected_anomalies.csv` |
| Rule-based checks | `nia/checks.py` | 14 SQL checks: completeness, uniqueness, referential integrity, capacity, status consistency, NRI-GIS reconciliation, underutilisation, aged work orders |
| Retrieval | `nia/retriever.py` | Section-level chunks, TF-IDF (1-2 grams); runs offline |
| Tools + guardrails | `nia/tools.py` | Single-statement SELECT/WITH only, keyword blocklist, DuckDB `enable_external_access=false`, row cap |
| Agent | `nia/agent.py` | Claude Messages API tool-use loop with token/time tracking and a max-turn limit |
| Evaluation | `nia/evaluate.py` | Check, retrieval and agent suites; results to `results/` |

The agent evaluation questions are written in plain operations language and **do not state the thresholds or scope rules** (e.g. the 10% route-length tolerance, or that Planned cables are excluded from GIS reconciliation). The agent has to find these in the docs.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python -m nia.generate_data          # (re)build data/*.csv
python -m nia.checks                 # run all SQL checks
python -m pytest -q                  # 21 tests, no API key needed

export ANTHROPIC_API_KEY=...         # Windows: set ANTHROPIC_API_KEY=...
python -m nia.agent "Which NRI cables are missing from GIS?" -v
python -m nia.evaluate agent         # full agent evaluation (14 questions)
```

## Results

| Suite | Metric | Result |
|---|---|---|
| SQL checks vs injected anomalies | precision / recall | 1.00 / 1.00 (98 anomalies, 12 types) |
| Retrieval (17 labelled questions) | hit@1 / hit@3 / MRR | 0.71 / 0.94 / 0.82 |
| Agent vs SQL answer key (14 questions, `claude-sonnet-5-5`) | mean precision / recall, exact match | 1.00 / 1.00, 14/14 exact |
| Agent behaviour | doc search rate, mean tool calls, total tokens | 100%, 4.4 per question, ~131k |

Caveat: the data is synthetic and the rules are clearly documented, so this is an easier setting than a real inventory. The next step is to make the eval harder: ambiguous questions, conflicting docs, and messier data.

## Project structure

```
nia/        generate_data, db, checks, retriever, tools, agent, evaluate
docs/       data dictionary, data-quality standards, NRI-GIS reconciliation,
            capacity & utilisation, field work orders, glossary
data/       generated CSVs + injected_anomalies.csv
tests/      pytest suite (agent loop tested with a scripted fake client)
results/    evaluation outputs (JSON)
```
